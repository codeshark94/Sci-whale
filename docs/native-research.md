# Native research runtime

A persistent primary session owns research decisions, source changes, tool selection,
interpretation and conclusions. Fresh prepared research and session-led Composer
research use the same `PrimaryClient` and native tool bridge. Composer binds this
owner by default; stage execution is an explicit compatibility mode.

## Tools and feedback

The primary can read, write and edit its research workspace. `research_tool`
provides repository discovery, source retrieval, acquisition, runtime inspection,
receipt reading and requested independent review. `research_run` executes complete
source in a declared or acquired runtime. It accepts raw stdout; an expected-value
comparison is optional. Available installed open-source implementations are supplied
with the assignment and can be inspected through runtime tools.

Known argument, file and program errors return their actual error or failed
observation to the same primary. They do not cancel it or invoke another author.
The primary chooses the correction. The runtime never automatically repeats a tool
call or dispatch. Duplicate transport call identities cannot execute twice.

Replies are archived automatically as `research-transcript.md`. Workspace notes
are optional. Historical stage contracts remain evidence; they are not current
research-output schemas or publication conditions.

## Independent review

`request_review` creates a separate session only on an explicit tool request. It
receives the supplied evidence, its own workspace and isolated computation tools.
It receives no primary development handle or producer history grants. Its feedback,
including rejection or unresolved findings, returns to the primary without an
approval veto. Computations and their limitations remain inspectable in actual
receipts; a review response alone does not establish scientific performance.

Each review dispatch retains its own receipt and usage even when two reviews have
identical evidence. Primary and reviewer usage are accounted separately. Review
interruption preserves the original unknown outcome. `reconcile_review` records
accounting recovery against the exact reaped receipt without inventing an answer.
Reconciling the primary transport does not reconcile an interrupted reviewer.

## Operational boundaries

Explicit user stops, finite dispatch deadlines, provider failures and unknown
executions remain operational events. Provider quota recovery needs actual capacity
evidence, including quota failures in a nested review. Healthy completed
continuations do not require another capacity confirmation. Source binding changes
preserve the same primary identity, paid receipts and historical usage.

A checkpoint records research progress. `research_finished` records the primary's
completion declaration; it does not rewrite historical stage verdicts or imply an
independently validated scientific result.
